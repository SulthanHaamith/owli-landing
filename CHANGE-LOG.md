- **2026-10-24 — Pay-button double navigation fixed (owner bug report) + regression harness.** The owner reported: *"After click pay button a new tab is opening and current tab is also moving to payment page which is not acceptable. Immediately fix this and add case such that it doesn't happen again."* **Root cause:** `window.open(url, '_blank', 'noopener')` returns **null even when the tab opens successfully** (the HTML spec makes the return value null whenever `noopener` is set) — so the `if (!w)` fallback treated every *successful* open as "popup blocked" and also ran `window.location.href = payment_url`. Result: the Coaxlure page loaded in the new tab AND hijacked the form page — exactly the reported symptom, on every spec-following browser. The "Reopen the payment page" link had the same flaw: its `preventDefault` only ran when `window.open` returned non-null, which never happens with `'noopener'`. **Fix (`js/event-register.js`):** the payment tab is now **pre-opened as `about:blank` inside the click gesture** (the only moment browsers reliably allow it), deliberately **without** `'noopener'` so the handle is real. It shows a short "Taking you to the secure payment page…" note (same-origin, writable), its `opener` is severed manually immediately (the protection `'noopener'` used to give), and only after `register.php` confirms is the tab pointed at the Coaxlure URL — **the one navigation**; the handle is then dropped so the form page can never touch the tab again. If the popup was truly blocked (or the attendee closed the blank tab early), the documented fallback runs: same-tab redirect, because no automatic tab route is left. **Every non-payment outcome closes the tab** — free coupon, validation error, `already_registered`, rate limit, network failure — no blank tabs left behind. The relink now runs `preventDefault` **always**, then the same about:blank pattern, with an explicit same-tab redirect only when popups are blocked. The module header documents this as the **PAYMENT NAVIGATION CONTRACT**, and the form note (`evf_note`, EN+TA + HTML fallback) now says the payment opens *in a new tab* instead of "you will be taken to". **Regression case (the owner asked for one): `scripts/check-pay-flow.js`** loads the REAL module in a Node VM with a fake DOM and enforces the contract across **six scenarios**: A normal payment → exactly one `about:blank` open, navigated once to the Coaxlure URL with `opener=null`, form page never navigates, polling armed, tab left open; B popup blocked → same-tab redirect only; C free coupon → tab closed, zero navigation, button re-enabled; D validation error → same; E network failure → same; F "Reopen the payment page" → `preventDefault` always runs, second tab to the same URL, form page stays. Exit code 1 on any violation, so it gates pushes/CI exactly like `check-i18n.js`; the old code's `if (!w)` branch is precisely what scenario A forbids — a successful open can never trigger a same-tab redirect. **Verified:** `node --check` clean; `node scripts/check-i18n.js` PASS (parity + runtime keys, new `evf_note` wording in both languages); `node scripts/check-pay-flow.js` **all six scenarios PASS**; 57/57 `scripts/validate.php` in the local stack; cache bump `event-register.js?v=6 → ?v=7` (events page, the only page that includes it). **Deploy note:** the fix is live only after the GitHub auto-deploy lands (~5 min after push); until then the public still sees the double navigation.

- **2026-10-24 — Same-page payment watching: Coaxlure opens in a new tab while the form polls and warns (owner request).** The owner proposed the hosted-checkout pattern: *"open the payments page in a new tab, check here continuously every second for the payment status then update based on it… show warnings while in the main page to not refresh or click back."* Adopted with two deliberate engineering changes. **Why new-tab + poll is right for this integration:** Coaxlure's `payment-link` API has **no return/callback parameter** (documented + verified during the blank-page diagnosis), so the attendee could only get back by finding their own way — with the page kept open and polling, "coming back" is no longer a step that can be lost. Also, the original redirect flow was a `window.location.href` navigation, which is exactly what made refresh/back stranding possible. **Change 1 — polling is NOT every second.** The first `status.php` poll fires immediately, then **every 2s for the first 30s, then every 5s**, capped at ~10 minutes (240 polls ≈ 30 Coaxlure API calls worst case — vs. one call/second = 600). Each poll hits `status.php`, which **verifies with Coaxlure server-side** (by stable order id, token fallback) — the browser is never trusted for payment state. `status.php` already self-throttles Coaxlure rechecks to one per 5s per attempt (`last_checked_at`), and browsers coalesce parallel timers, so the effective Coaxlure load is bounded regardless of client cadence. `rate_limited` (HTTP 429) from status.php's limiter stops polling cleanly — the API protects itself; the page never hammers. **Change 2 — the warning is honest, not a threat.** Added `evf_dont_refresh` (EN+TA) in a soft amber box: *"Keep this page open — do not refresh or go back. Your registration updates here automatically once the payment is verified."* Deliberately NOT `beforeunload` scare dialogs (browsers ignore them for reload anyway, and they read as hostage UI); the booking reference is stored in `localStorage` + the DB before redirect, so even if the attendee ignores the warning the data is safe — cron re-checks and the ticket downloads on their next visit to `/events/`. The warning protects the *experience*, not the data. **Flow shipped:** Pay click → `register.php` → `window.open(url, '_blank', 'noopener')`; if the popup is blocked the code falls back to the old full-page redirect (a navigation the browser cannot block); the main page shows the booking ID, a **"Reopen the payment page"** button (same attempt — no new order, no double charge) and the amber warning; on paid the box flips to the green paid state with the ticket download; on ~10-min expiry the box says the link expired and re-enables the form (the row stays pending; re-submitting creates a fresh attempt). New EN+TA keys: `evf_wait_open`, `evf_wait_checking`, `evf_reopen_pay`, `evf_dont_refresh`, `evf_timeout` (i18n parity PASS 347/347, runtime-key check 37/37).
